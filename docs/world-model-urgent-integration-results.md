# PR #18：冻结 V4 世界模型在急诊与动态复检场景中的真实集成结果

**裁决：接入与安全验证 GO，已发生实际预测和动作差异；额外急诊按时收益未观察到，V4 相比同评分的 Rule 未显示综合调度优势。**

这是实际运行的冻结神经网络，不是仅做可行性讨论。本轮未训练、未使用 GPU，复用了既有急诊/动态复检合成业务场景以及同一真实仿真器。**所有场景均为此前已查看的 4 Smoke + 20 Development；不是独立泛化测试，更不是迈克生物生产数据。**

| 指标 | P0 原 CP-SAT | P1 急诊优先 | P2 ETA | P3 解析风险 | P4 Rule 滚动 | **P5 V4 滚动** |
|---|---:|---:|---:|---:|---:|---:|
| 急诊按时率 | 52.78% | 52.78% | 52.78% | 52.78% | 52.78% | **52.78%** |
| 急诊逾期下界 tick/job | 24.35 | 13.89 | 13.89 | 13.89 | 15.86 | **15.86** |

| 常规任务受限流转 tick/job | 133.46 | 141.89 | 141.81 | 141.81 | 149.10 | **150.28** |

P0–P3 数字来自既有封存的 urgent_workflow_feasibility/evidence/summary.json；P4/P5 来自本轮实际新集成。都采用同一类合成任务与任务级业务指标，但旧策略与新策略计算预算、预测实现及评分方式不完全相同，**P0–P3 对 P4/P5 只是系统级参照，不是单因素世界模型因果归因**。真正受控的模型替换是 P4 vs P5。

与 P4 相比，P5：

1. 急诊按时率完全相同，急诊平均逾期下界完全相同。
2. 急诊未完成率宏平均下降约 **1.39 个百分点**，但这个差异来自 **seed=904388 一组**：某个急诊任务由观察终点仍未完成，变成**恰好在 tick=165 完成**；该任务仍然逾期，且由于截断定义，两策略的急诊逾期下界和受限流转值完全相同。这是观察窗口边界的脆弱差异，不是稳健的急诊时效改善。
3. 常规任务受限流转平均 **增加 1.18 tick/job**，所有任务受限流转平均增加 **0.77 tick/job**。
4. 在 seed=904096，P5 使常规任务受限流转由 **139.00 变成 158.67 tick/job**，比 P4 恶化 19.67；其中常规未完成率由 1/3 增至 2/3，但急诊结果不变。部分其他场景常规流转小幅改善，说明不是全面负收益，但总体没有正向证据。

**当前不支持“V4 改善急诊按时完成率”，也不支持“滚动世界模型调度优于已实现的简单急诊规则”。**

## 3. V4 的预测确实进入了调度决策

24 组合成场景合计：

| 对照项目 | 结果 |
|---|---:|
| V4 实际服务事件查询 | **7,808 条** |
| P4/P5 各自实际调度决策次数 | **376** |
| 两轨迹严格共同观察状态 | **306** |
| 其中至少两个合法候选的共同状态 | **297** |
| 共同状态的候选评分发生变化 | **260** |
| 完整候选排序发生变化 | **14** |
| 最终合法动作发生变化 | **10** |
| 同状态合法候选集合不一致 | **0** |
| 资源、运动、生命周期违规 | **0** |

评分、排序和动作比较是按 tick、完整可观察状态哈希、候选匹配身份和顺序严格配对，不把策略执行后的不同事实轨迹强行按 tick 比较。这次与以前 V4 对急诊业务未集成的纯审计不同：**模型预测不但改变数字，也实际改变了 10 次可执行调度动作。**

但发生动作变化不代表其业务后果改善。这 10 次动作翻转覆盖的场景里，7 组有常规时效变化、1 组有截断边界上的急诊完成变化、2 组在本轮主指标下结果相同。完整场景轨迹继续使用各自实际策略执行，不能把整个场景结果变化严格归因于某一单次动作。

## 4. CPU 成本与可靠性

| 指标，全部 24 组 | P4 Rule | P5 V4 |
|---|---:|---:|
| 整个真实仿真执行 CPU 进程秒总和 | 20.32 | **26.00** |
| 其中滚动预测 CPU 进程秒总和 | 13.63 | **19.27** |
| 实际服务事件模型查询 | 0 | **7,808** |
| 实际候选预测步数 | 17,055 | **17,145** |
| 安全违规数 | 0 | **0** |

总仿真 CPU 时间约多 **5.68 秒（28%）**；滚动预测 CPU 约多 **5.64 秒（41%）**。两个方案的预测步数差 90，原因是实际动作变化导致后续可执行候选轨迹不同，因而这些是观察到的系统总成本差异，不是严格相同工作量下的神经前向微基准。7,808 是服务事件查询数，不等于 7,808 个独立模型批前向调用。

V4 还记录了 not_started、observed_device_pause 两类合法“不查询/回退至规则”情形，**不等于程序异常**。本轮没有出现模型读取失败、非法候选或安全违规。

本次专用模型集成的两个运行阶段合计约 **47.17 CPU 进程秒**（含同场景 P4/P5 仿真及实验统计），不含安装依赖和旧 PR CI。原提交额外触发仓库其他既有 pull_request 检查；这些不能计为本轮专用实验耗时为零，具体 CI 账目应单列。

## 5. 当前可以确认的实际短板

1. **业务目标遮蔽：** 首层仍必须最大化当前急诊任务覆盖，模型无法推翻这一级决策。10 次动作翻转说明遮蔽并非绝对，但会显著限制预测发挥作用的状态集合。
2. **预测对象过窄：** V4 仅预测已经开始服务的会话下一步完成事件，并不预测未来复检真值、队列完整时序、设备故障、最终任务按时概率。这是模型与全流程目标的接口限制，不是权重训练失败的证明。
3. **动态复检的明确近似：** 当前滚动预测在真实复检结果公开前只用公共默认工作流；真实 Simulator 检测完成后才可能创建额外复检。这是有意采取的合法、但不完整的未来假设。不能将其表述为 V4 已学会条件复检。
4. **单个有利边界案例很脆弱：** 唯一急诊未完成率差异是一个 job 恰好在最终 tick 完成，不能据此宣称模型普遍改善急诊风险。
5. **常规任务可能被损害：** seed=904096 出现较大负面效应，说明预测驱动的局部排序变化可能把常规任务延后，而本轮模型没能改善急诊按时率抵偿这项损失。
6. **没有独立确认：** 同一批既有合成场景已被多轮审计，本轮只验证真实集成、风险和待诊断现象；不能以它们报告统计显著性或独立泛化。

## 6. 下一轮仅需针对真实失败做小范围修复与诊断

不要再停留于“世界模型有无理论价值”的空泛讨论。本轮已有实际接入结果。

优先追踪已有原始案例：

- seed **904096**：为何 V4 选择变化后常规任务流转恶化 19.67 tick/job，具体改变了哪一次任务分配和阶段等待？
- seed **904388**：为什么 V4 只让一个急诊任务恰好在观察边界 tick165 完成，而没有改善任何按时率或逾期下界？
- seed **902147**：实际出现小幅常规任务流转改善 2 tick/job，用以对照前两项，避免只看失败案例。
- 同状态下 **260 次评分变化 → 14 次排序变化 → 10 次动作变化**，审查评分量纲、预测状态和动作变更的真实路径。

此后若发现明确接口缺陷，先修复适配器并用**新冻结开发协议**复测；不能在现有结果上偷偷改评分直到 V4 胜出。若只是模型无法预测真实条件信息，应明确停止继续增强同一 V4 服务 hazard。

**下一阶段应当针对实测案例进行问题修复，而不是先重新训练或重新创造一个业务场景。**
