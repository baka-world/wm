# 本地 GPU 接入：现状、准备工作和分工

## 用户澄清与目标

2026-11-07：GitHub Actions 主要用于测试和复现；后续计划使用用户自己的本地 GPU 运行模型。现阶段继续使用 CPU 验证，不启用付费云资源或云端 GPU；不修改上游项目，未经用户确认不合并 PR。

用户希望将时间集中在模型相关内容；场景、数据、接口、训练运行框架和自动化验证由项目执行方准备，不能把这些工作默认转交给用户。尚不知道实际本地 GPU 型号、显存、系统、驱动、CUDA 或接入方式。历史对话中提及的 V100 16 GB 只是线索，不能当作已核实的本机配置。

## 当前能做什么，不能做什么

| 事项 | 当前实现 | 距离本地 GPU 运行的差距 |
| --- | --- | --- |
| 场景与仿真 | [两张有来源的地图和多机器人任务](multiple-locations-experiment.md)、状态记录及自定义分配回调已存在 | 模型只能看到已建模的约束；真实样本 SOP、容量、外生故障等仍需来源或明确标为仿真假设 |
| 状态与动作 | [Observation、Assignment、DynamicsModel](../lab_transport/transition_schema.py) 已定义；[训练数据导出器](../lab_transport/training_data.py)可把两张固定地图的仿真轨迹按场景分组导出，并检查来源、重复、时间边界和离散路线 | 尚无面向任意新地图的统一导入，也没有神经模型所需的多步样本加载、张量化、批处理及掩码接口 |
| 现有模型 | [状态转移模型](state-transition-revision.md)是 Python 实现的两组线性分类器，已经在 CPU 训练和离线测试 | 它没有 PyTorch/CUDA 训练路径，不能仅增加 `--device cuda` 就使用 GPU；目前结果是基线，不是要交付的最终 GPU 模型 |
| 调度衔接 | 仿真器可调用自定义分配回调，校验重复或当前不可用的任务分配 | 状态模型尚未真正连接候选动作评估、预测步进、保守回退及闭环对照；还没有模型调用的等预算计数 |
| 本地运行 | 模型与仿真已有 CPU 复现命令 | 尚无面向本地 GPU 的神经模型训练入口、设备检查、环境锁定、断点恢复和经过本地 GPU 实测的命令 |

现有 [草稿 PR #2](https://github.com/lieuyimo/wm/pull/2) 的分支为 `feature/sample-transport-prototype`，基于尚未合并的 PR #1；不能假定默认 `main` 已包含这些代码。

## 由项目执行方完成的准备

以下是需实现与验收的工作，不表示已经完成。模型架构与训练接口应允许协商，不先把某一种网络当作用户已经选定的方案。

1. **数据管线**：已针对两张固定地图完成按整场、种子、地图和任务时间表分组的导出与检查，包含图结构、实际动作、已知状态、下一观测及来源清单；仍需根据模型定义补充多步样本、张量批处理和掩码。避免相邻轨迹跨组，防止未来任务、中断、实际剩余服务时间和测试标签进入输入。首轮曾出现不同种子生成相同时间表，导出器会拒绝跨集合的重复时间表。
2. **模型适配边界**：明确输入是当前可观察状态、地图与候选动作，输出是哪些状态、事件概率或不确定性；未知未来任务和故障必须单独表示。提供可替换的模型适配接口和批处理，不要求用户修改仿真器。已有线性模型保留为对照。
3. **本地训练基础设施**：实现可配置的 CPU/CUDA 训练命令、依赖与环境说明、模型和优化器检查点、断点恢复、种子和配置记录、基本资源与错误报告。显式指定 CUDA 却不可用时应清楚失败，不得静默回退为 CPU。具体框架与依赖版本应在确定模型和系统条件后锁定。
4. **预测与调度闭环**：让模型对当前可执行候选动作预测，并通过现有回调选择执行；真实仿真器继续检查其实现的离散约束。明确计算预算、预测失效/不确定性处理，和规则基线使用同样输入与扰动。
5. **自动化验证**：GitHub Actions 只在 CPU 上进行数据、接口、训练流程及小型冒烟测试，检查无未来信息泄漏、分组和恢复；分别比较单步、多步和闭环指标。GPU 可用性与显存表现必须在实际本地设备另行验证，不能由 CPU 测试推断。
6. **交付**：准备版本固定的代码、数据生成及本地运行说明、模型接入示例、产物与日志说明。地图和临床数据的获取与再分发须按来源许可处理；人工示例不写成医院实测规则。

## 何时需要用户介入

- **模型方案对齐时**：执行方应先提交可审阅的状态、动作、输出、训练目标与备选网络方案。用户可以聚焦选择或确认模型方向；如果用户没有特别偏好，执行方先提出合理基线。工作区现有交接文档没有此前“分层模型”的完整结构，不能声称已准确复现其细节；确认该结构前，先推进不依赖网络选型的数据和接口工作。
- **本地 GPU 真正接入时**：执行方应先交付可复现命令和 CPU 冒烟测试。若能连接用户授权的本地环境，由执行方检测 GPU、显存、驱动、CUDA/PyTorch 和路径并运行测试；若无法连接，只提供少量明确命令供用户执行并回传文本结果，不要求截图或让用户自行处理框架代码。不能先声称真实 GPU 验证已经通过。
- **业务或论文要求只能由用户提供时**：如导师指定的样本范围、模型结构、论文格式或可用的真实业务资料。没有资料时可先使用已注明来源和假设的仿真场景，不凭空补齐临床规则。

### 固定地图数据准备入口

```bash
python -m lab_transport.training_data export --download-sources --profile full --output runs/local-gpu-data
python -m lab_transport.training_data validate --dataset runs/local-gpu-data
```

导出器从固定提交读取四个公开源文件并校验 SHA-256，生成地图拓扑、逐场真实执行的仿真轨迹及清单；`--profile smoke` 用较小规模测试管线，也可改用四个本地源文件路径。所有任务和扰动仍是合成仿真，不是临床记录。`manifest.json` 中的种子、场景指纹和结果只用于复现与分组，不得输入模型；下一观测是监督标签。输出包含地图衍生数据，仅保存到指定目录，不自动上传，分享前须核查源许可及数据权限。该步骤不依赖 GPU，也不训练模型。

2026-11-07 已在当前云端工作区用本地缓存的固定源文件实际生成 `runs/local-gpu-training-data` 并通过验证：训练 48 场 / 11,848 条转移，验证 16 场 / 3,988 条，医院测试 16 场 / 3,904 条，诊所测试 16 场 / 1,529 条，共 96 场、21,269 条转移，约 76 MiB。所有场次完成；任务时间表跨集合无重复，逐场文件和地图均有校验值。每场最终 `end_of_run` 转移被排除，未释放任务和服务真实倒计时不进入当前观测。这仍是小规模仿真数据，不足以代表真实医院或完成网络训练数据的全部准备。

## 进入 GPU 训练前的完成标准

- 已提供 CPU 命令生成并检查两张固定地图上带版本、来源和分组的训练/验证/测试数据；后续仍需与选定模型的数据加载、掩码和批处理衔接。
- 选定或提供的神经模型能通过统一接口完成一个 CPU 小批次训练、保存/恢复、推理和仿真对接；自动测试覆盖数据、泄漏与基本闭环。
- 本地 GPU 环境被实际检测；同一入口在明确指定 CUDA 后完成前向、反向和一次检查点保存/恢复，记录运行设备与占用。若本地 GPU 尚未连接，此项保持未验收。
- 提供可复现的完整训练与评估命令，明确数据、模型、输出位置和失败恢复方式；实验结果不能因指标或硬件假设被提前认定为成功。
