# PR #18：急诊字典序剪枝与 V4 计算成本回归（预执行协议）

## 已有实测数据的定量机会

先前真实的 12 个合成确认场景（GitHub Actions 42986822400，artifact 13840027102）保存了 P4/P5 的全部候选分数。现有调度评分的首层是当前未覆盖的急诊 waiting 数量，而且采用严格字典序。只要某候选首层大于同状态其他候选，后续 ETA、服务概率和队列分数无论如何改变都不能让它成为首选。

从原有 JSON 已计算：P4 的 578 个候选中 **236** 个在首层已经严格落败（40.8%）；P5 的 576 个候选中 **240** 个（41.7%）。这只是**潜在可省去的候选预测数量**，真实 CPU 收益需要运行验证。

## 实施内容

在隔离实验适配器增加可选 \`--evaluation-mode dominance\`：
- 对每个当前状态生成的合法 CP-SAT 候选，先只统计遗漏的已释放急诊任务数；
- 找到该第一层的最优值，跳过所有严格较差候选的 H5 + 20 tick 预测；
- 所有并列最优第一层候选依旧完整评价，使用原来的完全相同分数、候选索引和 tie-break；
- 两个模型 P4 Rule 和 P5 冻结 V4 使用同一剪枝条件；
- 跳过的候选必须在日志中明确 \`evaluated=false\`、\`score=null\`，不得伪造预测值。对这些候选也不得声称能比较完整排序；
- \`--evaluation-mode full\` 保留作为未经优化的原始参考。

冻结 V4 权重 SHA：\`60c8a6c3d832da3e6519072688ea099f64ae120ba19d3bd2ec705f7f1a11ac0c\`；其他 H=5、规则终端=20 tick、3 粒子、4 候选、随机键控、公开状态、真实仿真和任务指标都不变。不训练、不改 CP-SAT 或运动规划。

## 冻结的实际测试

1. **历史不变性：** 在全部之前确认的 12 个场景上运行剪枝版 P4/P5，与原 Actions \`13840027102\` 的 \`confirmation/cases.json.gz\` 严格逐场景、逐决策对比。历史哈希、事件哈希、最终动作、业务指标和未剪候选每粒子预测都必须相同。
2. **新合成场景不变性：** 新 index 36–43，seed 分别 906001、906098、906195、906292、906389、906486、906583、906680，代码运行前先冻结于 \`pruning_check_protocol.json\`。先用原始 full，再用 dominance，必须完全一致。运行 P0–P3 供实用性对照。
3. **效率：** 记录原始/剪枝后候选数、V4 服务预测查询、有效 rollout 数、总 CPU 进程时间与预测 CPU 时间；不得用节省候选数直接冒充节省 CPU 比例。
4. **解释原 6 次动作翻转：** 从上一轮封存的 \`confirmation/summary.json\` 机械提取严格同状态动作差异，逐项给出原 Rule/V4 候选和分量、对应全场景结果差值；不能声称整个轨迹损失由单次动作造成。
5. **安全：** 两个版本均必须通过资源、运动、生命周期、动态复检真实性检查；不得产生实际调度差异。

本轮考核是**不改变结果的计算成本削减**。即使原 Rule/V4 性能不佳，剪枝成功仍是有效工程优化；不能凭此声称 V4 比 P1/P2/P3 更优。新合成场景只用于不变性与运行成本回归，不是迈克生物实际部署数据。

结果和 SHA 校验追加到此报告，原历史归档只读保留。PR #18 保持 Draft，PR #19 不动。

### D. 最终工程裁决

1. **无损计算优化 GO**：严格字典序剪枝在 12 旧 + 8 新的合成场景中分别跳过 41.25%、38.81% 候选，保留所有真实调度行为和任务指标。
2. **CPU 效率实测正向**：在新 8 组同流程配对下，总 CPU 成本下降 32.9%，V4 服务事件查询下降 22.86%。这证明了少算不可能赢的候选确实有工程价值。
3. **世界模型业务增益仍未稳定**：新场景 V4 没有提高急诊按时率，也没超越简单急诊优先规则。不能将省计算写成神经世界模型效果提升。
4. **并非在线实时性证明**：本轮测的是 GitHub Actions CPU 进程时间，没有真实设备调度事件的延迟 SLA、尾延迟或商业机器人部署指标。
5. **研究边界继续保留**：原仿真只针对轮式多机器人与公开业务参考的合成样本流转，不涉及生产网络或真实检验 TAT；冻结 V4 仍只预测服务完成事件，不会提前得知复检真值与设备异常。

**下一阶段不应继续在已经查看的 20 组场景上调节模型或评分。若目标是系统工程实现，可以把这次严格验证的无损剪枝保留在实验适配器，并将 P1/Rule 作为实际工程默认基线；冻结 V4 作为可选择的预测调度实验策略。**
