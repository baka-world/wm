## 冻结实验设置

- 只查看已经在前次实验中暴露的 `906195:138`。因此属于**事后机制解释**，不是盲测或泛化。
- 两个原始合法候选，8 个已经冻结的预测采样 seed；固定 V4 checkpoint、H5 rollout、三粒子、公共合法动态以及所有字典序业务分量。
- 三个终端估计只在 H5 后切换：`optimistic`（乐观剩余工作量）、`budgeted_queue`（20 tick 规则排队续推）、`rule_continuation`（到场景结束/任务全部完成）。
- 两个 prefix 模型分别是 P4 Rule 与 P5 V4；每个模型/终端配置对所有候选使用同样采样种子。P4 本身确定性，8 个种子结果相同不应解释成 8 次独立试验。
- 业务参考来自前次冻结反事实实验：在同一已发生前缀、共享外生事件和**相同 P1 后续策略**下，两候选急诊按时率和逾期下界相同；候选0常规平均受限流转 **154.00 tick**，候选1为 **152.67 tick**。故候选1在该固定合成未来和原 `judge_score` 下更优。不能把它称为真正的条件期望最优。

## 主要实测结果

下表为 8 次重复中选择候选0/候选1的次数：

| H5 前缀模型 | 终端估计 | 候选0 | 候选1 |
|---|---|---:|---:|
| P4 Rule | 乐观 | 8 | 0 |
| P4 Rule | 20 tick 排队续推 | 0 | 8 |
| P4 Rule | 完整规则续推 | 0 | 8 |
| P5 V4 | 乐观 | 8 | 0 |
| P5 V4 | 20 tick 排队续推 | 8 | 0 |
| P5 V4 | 完整规则续推 | 6 | 2 |

- **终端价值估计参与了动作翻转。** P4 仅切换终端估计即可从候选0稳定改变为候选1。
- **不能把错误完全归结为短终端。** P5 在 20 tick 续推仍然 8/8 选候选0；完整规则续推也仅有 2/8 改选候选1。完整规则续推同样是代理，不等于真实未来。
- **前五步模型选择与终端估计存在交互。** 相同规则终端、相同候选及采样种子下，P4/P5 排序仍可以不同。不能据此区分是 V4 的概率错、离散状态传播误差，还是任务级代理表达能力不足。
- V4 总真实服务事件模型查询：`168 × 3 = 504` 次（每种终端模式各168次），P4 没有神经服务查询。20 tick 模式的规则续推总计每臂960个模型步，完整规则续推每臂1056步。

## 裁决和下一步门槛

**机制定位 GO，稳定调度增益依然 BLOCKED。** 对 `906195`，短终端代理可能是问题的一部分，但仅仅延长规则续推不能可靠修复 V4 对候选0的偏好。当前没有证据支持重新训练、调权重或增加样本数以获得稳定业务收益。

若继续隔离，应在不变更上述已见结果的前提下，单独冻结一个 CPU 实验：记录真实一步服务事件标签与 V4/Rule/B2 的对应公开条件概率，接着在同一预测状态下比较固定终端代理的任务级排序；必要时为同一合法决策状态生成**多组真正独立且跨候选配对**的未来外生事件。上述检验必须与本轮已查看案例的事后分析严格分开，不能把单一合成未来的结果当作可部署增益。
