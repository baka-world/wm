# PR55：世界模型训练数据的质量优先扩充与真实动态审计

## 研究决策

在PR53/PR54的时序R-GCN和真实业务调度仿真上，**先建立数据覆盖、行为反事实信号和可信状态转移的质量评价，再决定是否采集200+场景**。当前不授权“随机种子×4”作为数据扩张，也不进行GPU或模型训练。

上一阶段的事实：
- 原数据源PR54仅使用固定7×5网格、3台机器人，三个stress场景和不同隐藏设备持续时间；每场景先取56个公开tick，60场景3360实际一步状态转移。
- 4步历史GRU/R-GCN比只看当前快照，独立12场景一步节点MSE有15.2%改善，但设备Brier退步；尚未证明长期递归或在线调度收益。
- PR52已显示仅增强损失或动作排序不能替代可靠的动作条件状态动态；决策损失带来的候选后悔值改善与节点预测校准存在冲突。

因此本轮提出的**质控门禁是训练之前的研究条件，不是宣称已经拥有高质量训练集**。

## 本轮可执行数据方案

源代码位于 `experiments/world_model_integration/quality_pr55/`，全部继承已经审计过的`BusinessSimulator`、`BusinessCPSAT/TrueCPsatBranch`、`PublicTransitionCollector`，不更换运动学、任务工作流或真实状态转移规则。

`protocol.json`预先冻结18个**只用于开发和审计，不称为独立盲测**的真实仿真场景。各压力类6个情景，每类分别采用：

| 环境配置 | 真实变化 | 为什么要有 |
|---|---|---|
| baseline | PR48原始业务场景 | 与过去训练数据同源，确保回归 |
| higher_demand | 拥堵任务14→18，其余12→16 | 学习高任务负载和排队 |
| capacity_relief | 共享工作站资源A的容量1→2 | 区分设备故障和资源容量变化 |
| fewer_robots | 机器人3→2 | 改变可行任务分配和等待演化 |
| slow_service | 工作站B0、C服务步数和prior各+2 | 增加服务持续时间与队列差异 |
| shifted_releases | 在事实生成器中变更任务到达节奏 | 学习新任务何时才可见和到达后的变化 |

每个stress组依然分别包含原故障持续时间支持内/更长故障；隐私性的故障终止和未来任务表始终只存在于**真实事实仿真器**，不能作为预测器输入。

注：上述配置保持原**7×5网格不变**，不能被包装为跨地图泛化。跨地图及机器人形态变化必须单独建**新预注册数据协议与拓扑留出集**，并先修正模型中位置归一化假设；本轮没有证据证明该项已完成。

## 状态真实性、时间泄漏与标签质量

1. 真值由原始`BusinessSimulator.run(on_transition)`给出的**真实t→t+1公开状态**计算，`BusinessObserver`只看到t及以前。逐节点字段对齐原PR52状态目标和原PR51公开图；动作边来自t时刻真实合法已执行CP-SAT分配。
2. 每场景保留从t0到**真正终止tick**的全量状态转移，**不再固定切到前56个tick**。同时报告前56个和其后的真实事件，检验以前的时间截断漏掉哪些故障恢复、任务进度、队列变化。
3. 审计`station_fault_onset`/ `station_recovery`/ `new_task_release`/ `assignment`/ `task_status_change`/ `task_completed`/ `robot_phase_change`/ `capacity_transition`/ `queue_transition`和机器人移动变化。全部来自真实前/后公共状态变化，而不是私有预定日程。
4. 不把同一场景高度相关的多个tick当作独立训练场景或独立测试。记录每个场景原始样本数、语义去时钟漂移的公开状态签名重复率、事件分组、真正完成/超时状态和违规。
5. 从真实raw生成最多72个**训练开发预览**样本：按少数事件覆盖、相邻真实历史上下文与均匀正常样本确定性抽样，**仍完整保留原raw事实**。此抽样明确是根据t+1事件标签进行的**训练集目标分层抽样**，不能用于未见验证/独立TEST的样本筛选，也不能据其事件比例估计部署自然频率。未来概率校准必须以自然不经标签筛选的完整时序分布为准。

## 在生成数据前冻结的自动入场门禁

`pr55_gate.py`验证整个源Artifact、原始事件和当前图一致性，并输出不可覆盖的`quality.json`：

- **完整性**：18场景、同一源commit和协议SHA、每场景的连续真实tick、没有空白、没有缺失t+1标签、业务资源/运动/工作流安全检查全部通过。
- **因果**：每行公开历史最后tick恰好是t，真实标签恰好是t+1，未来未公开任务和设备真实终止表不得进入特征，任务完成数不能超过新增可见任务数。
- **动态覆盖**：真实场景中至少发现5种指定不同事件类别，必须有设备故障、设备恢复、任务发布、任务状态变化和合法派单；真实晚于第56个tick的动态至少1条。
- **场景覆盖**：三种stress各6组，六类真实配置各3组；不得只复制相同参数换seed。
- **重复与样本平衡**：目标分层训练预览的无事件静态比例不得高于50%；忽略年龄和截止时间自然流逝后的公开状态语义唯一比例至少50%。静态比例和唯一性门槛均以`protocol.json`内的预注册值为准，不能根据试采结果调低门槛以制造PASS。
- **裁决**：全部满足仅输出`PASS_NEXT_PHASE_DESIGN`，否则`NO_GO_EXPANSION`并列出失败项；**无论结果如何，`training_ready=false`和`decision_aware_data_ready=false`**，因为此阶段不包含真正相同状态不同动作的反事实信息量测量，也没有新跨地图独立测试。

这样可以做到数据生成成功但质量不达标时**停在数据门禁**，避免错误数据大规模重复采集。所有原始失败/超时场景都必须保留和报告，不能暗中删除。

## 后续阶段通过条件（未获得授权直接执行GPU）

1. 只在试采符合门禁后冻结新的独立训练/验证/测试扩张协议，先针对缺失事件或低覆盖子群增量生成，而不是机械增加所有场景。
2. **反事实动作信息量门禁**：固定相同真实状态、候选集合与外生随机源，逐个合法动作产生真实下一步和H5/H20结果，验证动作改变是否真正带来不同状态及后悔值。必须在当前六种真实配置下重新执行，并确认没有把未来环境信息放进模型输入。此前PR52/53的反事实对照只覆盖固定资源/机器人配置，不能直接代替新场景证明。
3. **拓扑泛化门禁**：至少需要新地图、地理瓶颈/资源站点配置独立holdout；现有特征位置固定除以7/5，需要同步改为地图尺度归一化或可信拓扑表示，然后才生成跨地图数据。
4. 真正模型训练必须用完整自然验证/独立TEST，保持设备可用性Brier、动作后果敏感度、多步状态合法性、时间序列可重复性与真实CP-SAT闭环收益四项关键指标。
5. GPU暂不需要；大规模模型/递归H20训练时使用原[GPU交接Issue #54](https://github.com/lieuyimo/wm/issues/54)和[GPU Agent Prompt](../pr54-gpu-agent-prompt.md)，正式预算另行执行。

## 实际入口与归档

- `pr55_generate.py`：原真实CP-SAT运行、6种场景配置、full-episode时序、审计标签/开发性抽样；
- `pr55_gate.py`：独立、冻结指标的质量准入决策，不允许测试后调整；
- `test_pr55_quality.py`：配置确实改变真实仿真、公开特征不泄漏、事件识别、公开语义去重、保留完整事实；
- `.github/workflows/pr55-quality-first-data.yml`：GitHub Actions CPU三个矩阵worker并行运行，分别归档原始真值、source_sha、依赖锁和完整SHA256；独立聚合QA工作流输出`quality.json`。
