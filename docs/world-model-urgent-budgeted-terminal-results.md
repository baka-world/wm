## 1. 到底修改了什么

原 \`H=5\` Rule/V4 预测后，直接对所有当前可见任务求和乐观剩余工作量：忽略候选动作可能造成的后继站点排队与资源竞争。此前的 \`rule_continuation\` 能补足部分工作流先后顺序信息，但会逐 tick 模拟到工作流结束或 165 tick，CPU 成本高。

本轮新增 \`terminal_mode="budgeted_queue"\`：

1. **前 5 tick 仍是完全相同的 P4 Rule 或冻结 P5 V4 世界模型**；3 粒子，最多 4 个正式 CP-SAT 生成的合法候选，服务随机数按相同公开服务会话键控。
2. H5 后两臂使用**相同** \`ProgressAwareRule + WorkflowDynamics\`、\`nearest_batch\` 和容量/运动检查，最多继续 **20 tick**，保留共享资源排队和任务后继阶段释放的影响。
3. 截止后仍未完成的任务，使用原来的乐观剩余工作量估计。**不是完整队列时序预测，不是新的学习模型，也不是修正后的真实未来 Oracle。**
4. 公开观测之外的未来复检判定、故障、未释放新任务和私有服务时长一律不可读取。旧 \`optimistic\` 与 \`rule_continuation\` 两种入口保持不变。

## 2. 六策略确认场景结果：12 组 × 6 个真实执行

全部为**逐场景宏平均**。时效指标为合成任务最后阶段的完成情况，不是临床报告 TAT；受限流转对未完成任务做固定窗口截断。

| 方法 | 急诊按时率 ↑ | 急诊逾期下界 tick ↓ | 急诊未完成率 ↓ | 常规受限流转 tick ↓ | 全任务受限流转 tick ↓ |
|---|---:|---:|---:|---:|---:|
| P0 原始 CP-SAT | 55.56% | 24.764 | 25.00% | **136.111** | 119.915 |
| P1 急诊优先 | 55.56% | **14.903** | **2.78%** | 143.194 | 119.296 |
| P2 确定性 ETA | 55.56% | **14.903** | **2.78%** | 143.028 | **119.171** |
| P3 解析风险 | 55.56% | **14.903** | **2.78%** | 143.167 | 119.254 |
| P4 Rule + H5 + 20 | 52.78% | 15.931 | 5.56% | 150.361 | 125.004 |
| **P5 V4 + H5 + 20** | **58.33%** | 15.181 | **2.78%** | 149.556 | 123.594 |

**严格增量比较 P5 − P4（相同前缀架构、后续队列规则与评分）：**

- 急诊按时率宏平均 **+5.56 个百分点**，来自 **905147** 和 **905585** 两组各多 1 个按时急诊样本；
- 急诊逾期量下界 **−0.750 tick/job**，急诊未完成率 **−2.78pp**；
- 常规受限流转 **−0.806 tick/job**，全部任务受限流转 **−1.410 tick/job**；
- 严格匹配到同一可观察状态、多个合法候选的 **115** 个决策中，有 **98** 个候选评分变化、**11** 个排序变化和 **6** 个实际派单变化，合法候选身份/顺序不一致为 **0**。

**强基线比较 P5 − P1/P2/P3：**

- P5 急诊按时率高 **2.78pp**，但急诊逾期下界反而高 **0.278 tick/job**；
- 相比 P1，常规任务受限流转 **多 6.36 tick/job**，全任务受限流转 **多 4.30 tick/job**；
- P1–P3 的急诊未完成率与 P5 相同。没有证据表明 P5 目前是更优的工程方案。

**任务级微平均**（12 场景总共 24 个急诊任务）：P0/P1/P2/P3 分别都是 10/24 按时；P4 **9/24**；P5 **11/24**。宏、微平均不能混用。

## 3. 具体急诊成功与风险案例

- **905147**：P4 中急诊 U905147-1 于 tick90 完成且已超时；P5 于 **tick61** 完成、按时。相对 P1，P1 的该任务于 tick84 完成（仍逾期），因此此场景 V4 确实额外挽救 1 个急诊任务。但同场景还有其他急诊和常规任务的完成时间变化。
- **905585**：P4 中急诊 U905585-1 截止仍未完成；P5 于 **tick58** 完成、按时。但相对 P1，P5 让 U905585-0 从 tick50 的按时完成变成 tick160 的逾期完成，同时让 U905585-1 从 tick154 的逾期变成 tick58 的按时，因此对 P1 **没有提高该场景按时急诊总数**。不能只报告 V4 挽救 U905585-1 而隐去 U905585-0。
- **905220**：P5 相对 Rule 主要改善常规任务流转，未改变急诊按时率。
- 其余 9/12 组急诊按时率 P4/P5 相同；本轮急诊收益由两个合成场景驱动，不能推导稳定显著性或部署收益。

## 4. 计算代价与三组已知故障对照

新 12 场景的真实仿真 CPU 进程时间（含本体调度、候选评估与预测）：

| 方法 | 12 场景 CPU 进程秒 |
|---|---:|
| P0 | 2.89 |
| P1 | 2.97 |
| P2 | 2.87 |
| P3 | 2.95 |
| P4 H5+20 | **30.50** |
| P5 H5+20 | **33.10** |

P5 比 P1 总 CPU **约 11.2 倍**。它有 **3972 次真实 V4 服务事件查询**、约 **32,781 次规则终端预测步**；这两个计数分别对应神经服务事件查询和非神经公共规则续推，不得合并为“V4 前向次数”。本次单独确认批次约 **76.21 CPU 进程秒**（包括全部六臂与统计），不含依赖安装、既有 PR 旧 CI。

在三个**事先已看过、只用于诊断**的失败案例 902147、904096、904388 中：

| 三组两臂实际仿真 CPU 合计 | 原 H5 keyed | H5+20 budgeted | H5+全终端续推 |
|---|---:|---:|---:|
| Rule+V4 | **5.97 秒** | **19.98 秒** | **71.97 秒** |

预算化方案约为原 H5 成本的 **3.35 倍**，但比完整规则终端续推少约 **72% CPU**；它只部分恢复终端资源竞争信息。

三个已知案例的常规任务受限流转：

| Seed | H5 Rule / V4 | H5+20 Rule / V4 | 全终端 Rule / V4 |
|---:|---|---|---|
| 902147 | 156.33 / 153.67 | 154.67 / 154.67 | **144.00 / 144.00** |
| 904096 | 139.00 / 153.00 | **152.00 / 154.67** | **137.67 / 139.67** |
| 904388 | 157.00 / 157.00 | 157.00 / 157.00 | 157.00 / 157.00 |

尤其是 **904096**：预算化后 P5 相比 P4 的损失从 H5 的 +14.00 tick/job 收窄到 +2.67，但两臂的绝对流转都比原 H5 更差，也不如全终端。**不能把损失收窄解释为整个预算化方案改善了业务表现。**

## 5. 裁决与合理的下一步

- **工程 GO**：预算化终端规则续推、冻结 V4 真推理、动态复检和正式合法候选链路实际运行成功；新确认 12 组合成场景均完成，安全不变量通过。
- **V4 增量：有限正向证据，但不充分**：比共享架构的 Rule 多 2 个急诊按时任务，出现 6 个同状态动作改变。结果只由少量场景驱动，未证明稳健泛化。
- **与强基线比较：仍未胜出**：V4 相比 P1–P3 的急诊按时率略高，但逾期、常规任务时效和成本均更差，当前不值得替换生产级简单策略。
- **实时性待解决**：CPU 比 P1 多约 11 倍；20 tick 只是一个成本折中，尚无企业实际调度延迟 SLA。不要再通过不断扩大预测长度或调权重在确认集合上搜索。
- **下一步若继续，只应处理已有实测问题**：优化队列价值近似的成本/精度或减少无效候选预测，锁定策略协议后用**另一套真正未查看的合成测试**单次确认，再决定是否保留 V4 作为论文决策价值贡献。不得用本轮确认 seed 反复调参。

**本轮不支持“V4 已经成为最优调度算法”。但与前几轮纯评分审计不同，这里存在真实神经模型驱动、且在新合成场景中可追踪的急诊任务按时改善。**
