# PR #18：20 tick 预算化队列终端估计实验（冻结执行协议）

## 研究问题

已有冻结 V4 + H5 的实际测试已经证明神经服务完成预测可以改变可执行调度动作，但没有提高急诊按时率，且对三粒子采样与末端乐观剩余工作量近似敏感。2026-11-11 已完成的全终端规则继续模拟解决了部分排序错误，但每组候选在长达 165 tick 的工作流上继续模拟，CPU 成本过高，并未证明 V4 独有增量。

本轮不是再训练模型，而是将长终端模拟中的队列和阶段释放信息压缩为一个**预算固定的、最多 20 tick 公共规则连续预测**，后面仍使用原始工作量近似。Rule 和 V4 共享该终端接口。原 H5 的 Rule/V4 前缀、冻结权重、3 粒子、4 候选、急诊评分字典序、CP-SAT 和真仿真器不变。

## 预先冻结设计

- 三个已知诊断：902147 (index2 Smoke)、904096 (index19 Dev)、904388 (index23 Dev)，只用于分析失败变化。
- **12 个新合成确认场景**：index 24–35，seed 905001 + 73×(index−24)；任务数、急诊占比、复检率与停机组合仍按原公开合成场景函数给出。
- 新场景每组实际运行 P0 原 CP-SAT、P1 急诊优先、P2 确定性 ETA、P3 解析风险、P4 Rule H5+20、P5 V4 H5+20。不得只报告 P4/P5 相对改进，必须公开 P1/P2/P3 的业务指标。
- 主要指标：急诊按时率、逾期下界、未完成率；常规和整体受限流转；运动/资源/生命周期安全；CPU 进程时间与 V4 实际服务查询。
- 新确认场景全部运行，不因中途负收益挑选或跳过；如运行失败按实际结果标为 BLOCKED。原来的 24 场景仍是开发审计，不能与新确认集合混合平均。
- 新场景来自同一合成机制，因此只支持同生成器下的初步确认，不是企业泛化或临床 TAT 证据。
- CPU-only，零 GPU，零模型训练，checkpoint SHA-256 为 60c8a6c3d832da3e6519072688ea099f64ae120ba19d3bd2ec705f7f1a11ac0c。
