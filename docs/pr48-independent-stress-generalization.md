# PR #48：世界模型恢复动态的独立压力复测与可解释决策验证

## 研究起点

本科毕业设计：《基于世界模型的样本转运调度系统设计与实现》。在 [PR #47](https://github.com/lieuyimo/wm/pull/47) 的24组新合成案例中，按相同1.5秒CPU-process预算，**V4-H20 + 公开已知停机恢复**相对于原V4-H20得到8胜15平1负、平均完成时间缩短1.542 tick，CPU预算超限0次。这是已有条件恢复动态在少量单地图场景中的真实在线收益，而非训练新世界模型的结果。

本轮两个任务**分离执行**：

1. PR #47 的原始轨迹**只读归因**：当两模型预算内都完整评分时，第一个相同公开状态/候选池上的真实不同派单何时发生、是否真的由模型预测排名引起。绝不使用结果调整后续世界模型、CPU额度或压力场景。
2. 使用独立48个新合成场景进行完整**封存参数的三臂在线压力复测**，同时记录真实墙钟决策延迟与CPU成本。

这不是依据PR47测试结果挑选阈值或回归训练。我们保持原冻结 V4 SHA256 `60c8a6c3d832da3e6519072688ea099f64ae120ba19d3bd2ec705f7f1a11ac0c`，PR44 train-only KM、原 PR45 显式合法恢复事件、PR30 H20/P3 完成样本数评分、CP-SAT候选上限4及1.5秒CPU-process预算**全部不变**。

## 首次运行前冻结的48组新场景

预注册：`experiments/world_model_integration/stress_pr48/pr48_protocol.json`。三种压力类型，每类**16个以前从未测试的独立新种子**，并各含8个原停机分布、8个延长停机分布。已与PR44/45/46/47所有已记录新种子交叉校验、绝不复用。

| 场景类别 | 与 PR47 的差异 | 希望检验的动态 |
|---|---|---|
| 拥堵任务 `congestion` | 10→14个任务，统一在tick0发布，站点 A 容量1；1个工作站故障 | 任务与资源竞争更密集时，预测的恢复能否引导更好调度 |
| 多设备故障 `multi_fault` | 12个任务，两个不同工作站分别在tick7与tick13发生外部停机 | 已观测多个故障的恢复如何影响多站服务与路径/资源关系 |
| 分批到达 `staggered_arrivals` | 12个任务，发布tick为0/6/12/18；1个工作站故障 | 具有**不可提前观测的未来任务到达**时，模型对未知外部动态的局限 |

这仍然是既有7×5格子、3个轮式机器人、既有资源/工作流规则下的业务压力测试，**不是跨地图、跨机器人形态或真实企业数据泛化**。私人真实故障开始/结束时间仅在真实BusinessSimulator场景初始化时生成；恢复世界模型接收的仍然只有连续公开设备停机历史。分批到达的未发布时间任务在未来到来前不能作为已知候选进入模型。

真实机制中，原故障持续时间支持集：B0 [4,6,8,10]，B1 [8,12,16,20]，C [3,5,7,9]；延长故障持续时间支持集：B0 [9,12,16,22]，B1 [18,24,30,36]，C [8,12,16,24]。各次故障的持续时间根据固定新种子、故障序号和站点SHA256抽样，仅模拟器知道。多设备故障的两个站点不相同，原业务约束原封不动。

## 新48组测试的三个策略及统计

| 策略 | 候选及评分 | CPU预算 |
|---|---|---|
| 原始 CP-SAT | 原CP-SAT第一合法候选 | 不使用世界模型 |
| 原 V4-H20/P3 | 原CP-SAT候选，H20完成样本数最大化 | **1.5秒/决策** |
| 公开条件恢复 V4-H20/P3 | 完全相同的CP-SAT候选、评分、粒子与滚动预测，额外外生已知故障恢复 | **同样1.5秒/决策** |

所有决策先发生在真实未来尚未知的公开状态上；真实未来仅用于原业务模拟器实测结果。若超预算、模型合法性失败或候选不完整，沿用原PR30合法首提案回退，不用部分结果凑排名。

**主指标**是每组真实闭环完整makespan ticks，按场景种子配对恢复版与同CPU预算原V4，分别报告拥堵、多设备故障、分批到达及两种持续时间机制。记录赢/平/负、均值、中断/未完成任务、真实逾期数和资源/运动安全。若有未完成回合，明确记为截尾，不得把max_ticks视为真实完成时间的胜利。

**次要指标**是每次决策墙钟耗时P50/P95/最大值、每回合总CPU进程耗时、CPU超预算/回退、模型调用次数、候选翻转、资源等待、阻塞移动。CPU-process截止条件不是可中断wall-clock硬实时保障，真正业务SLA尚需单机负载条件下单独验证。

统计独立单位为48个新种子，而非每粒子或每tick；样本数较小，任何小幅总体均值收益都必须同时报告各类异质结果。**不能筛选困难场景后报告最好的分布，也不能从本轮结果修改KM、权重、评分或新限额再称独立验证。**

## 实现与归档

- `pr48_scenarios.py`：只改变真实场景生成机制，保留原BusinessSimulator、业务规则和网络。
- `pr48_online.py`：创建原PR30 `OnlineHorizonPolicy` 与PR46 `RecoveryOnlinePolicy`，唯一增加独立外层墙钟时间测量；其余预测与调度实现全部复用。按48个新种子做完整闭环、完整证据和分层指标归档。
- `pr48_readonly_pr47.py`：仅读取原PR47 Actions Artifact原始JSON和哈希，以共有公开状态前缀判断首次派单分歧，禁止重跑旧场景。
- `test_pr48.py`：检查真实新增多故障、14任务拥堵、延后发布、独立种子、训练与预算冻结；同时回归PR45的合法外生事件合同。
- GitHub Actions使用固定CPU锁文件、原V4检查点与原PR44归档SHA验证，三个场景类别独立CPU runner并行执行各16组/48条在线轨迹，再汇总全部144条结果。原始数据、来源commit、CPU依赖与SHA256均归档，原训练结果保持不可覆盖。

**晋升门禁：** 多机制新场景中相对原V4能重复正向、没有安全或逾期显著恶化、同预算实际成本可接受，才考虑默认世界模型恢复模块；否则总结在哪些条件下有效，以及由哪些外生未知事件造成泛化失效。PR保持Draft，不修改PR19、V4正式路径或主干。
