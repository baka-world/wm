## 本次补充：可观察的一步状态转移

新增 [transition_schema.py](../lab_transport/transition_schema.py) 和 [transition_data.py](../lab_transport/transition_data.py)。仿真器可选地记录：

1. 当前已释放任务、机器人位置和阶段、站点当前可用性及历史服务时长估计。
2. 该步**实际执行**的机器人—样本分配；无新分配时为空。机器人移动和站点服务仍由现有仿真控制器执行，并不是这个动作接口已经能控制全部行为。
3. 下一观测时刻的状态，以及正常完成或时间上限的标记。

输入不包含尚未释放的任务、未来中断区间、随机抽样结果或实际 `service_remaining`。已释放样本的类型、包装、温度条件及规则配置如有提供会被记录，它们是输入声明，不代表系统已经测量、核实或判定临床合规。绝对采集时间暂不进入转移记录；如需计算样本年龄，应先定义可靠的时间基准和数据权限。

**时间边界**：一般记录在第 `t` 步释放任务之后、分配之前采集输入；执行该步后，目标是第 `t+1` 步释放任务之后、分配之前的观测。因此目标中可以出现这一时刻才到达的任务或新发生的站点不可用，它们是事后标签，不得反向放入输入。最后一条 `next_boundary=end_of_run` 在仿真结束处采集，不处理结束边界的新任务释放，且用 `completed` 或 `time_limit` 区分结束原因；训练时应明确处理这一边界，不能把时间截断当作任务已完成。

原回放 `history` 供调试使用，包含真实剩余服务时间和尚未释放任务，**不能整份直接作为模型输入**。新增记录是信息隔离的基础，不构成进程级安全沙箱；模型训练代码仍必须主动限制特征。`manifest` 的种子、场景哈希、结果和记录数只用于追溯/分组，不能作为预测特征；样本 ID 也不应直接当作可推广特征，以免利用顺序或身份编码。

只记录实际执行轨迹，不产生未执行候选动作的真实结果。观测不包含全部隐藏状态：例如未来扰动、当前随机服务剩余量以及控制器内部恢复计划不可由当前一帧完整恢复；因此不能假设这组观测已构成确定性的完整状态。未来模型应考虑历史、显式不确定性或适当的已知控制器信息，并分别评价能预测的部分和不可预知的外生事件。

本次默认导出来自仓库的**人工网格示例**，不是临床数据。导出器仅支持现有 JSON 网格输入；医院或诊所图可由 Python 调用相同仿真器的记录回调，尚未提供通用地图 CLI。导出文件可能包含输入任务的标识和属性，使用实际业务数据前应核实授权及脱敏要求。源地图及患者记录不会因为定义接口而自动获得再分发许可。

CPU 示例：

```bash
python -m lab_transport.transition_data --scenario scenarios/laboratory_demo.json \
  --policy world --seed 42 --output runs/transitions-demo
```

输出 `transitions.jsonl` 与 `manifest.json`，不会覆盖非空输出目录。此命令只采集数据，不训练模型。[测试](../tests/test_transition_data.py)检查开启记录前后仿真结果一致、记录的分配与执行事件一致、隐藏服务剩余和未来任务不进入当前观测，以及任务释放和截止边界。

## 自定义分配策略接入点

`Simulator.run(dispatch_policy=...)` 可在有空闲机器人和等待任务时，向回调传递当前 `Observation` 以及候选 `Assignment` 组合。回调可选择零个或多个分配；仿真器在应用整批分配前检查对象类型、任务与机器人当前可用性、以及同一机器人或任务是否被重复选中。空分配表示等待，可能导致仿真超时，不会被自动改写为成功。

```python
from lab_transport.domain import load_scenario
from lab_transport.simulation import Simulator

def first_candidate(observation, candidates):
    return (candidates[0],)  # 仅为接口演示，不是推荐调度算法

scenario = load_scenario("scenarios/laboratory_demo.json")
result = Simulator(scenario, "world", seed=42).run(dispatch_policy=first_candidate)
```

这个接入点可供将来的模型辅助选择，但**不会自动构造或训练模型**。候选是空闲机器人与等待任务的组合；批次校验不等于证明路径全局可行、业务规则全部满足或真实机器人安全。移动和站点执行仍使用现有仿真规则；回调尚不能手动逐步控制仿真、替换路径规划器或切换到 Lay2Graph。已有单元测试使用自定义策略完成示例闭环，并检查重复/不存在的分配在任何分配状态修改前被拒绝。由于回调可能多次或从未评估某个候选，现有指标将自定义策略的候选评估次数记为未知，不把展示的候选数冒充计算次数；后续公平预算比较需要明确的计数接口。

## 下一步实施顺序

1. **继续完善接口**：在已有的自定义分配回调上，设计模型预测结果和可单步推进的仿真接口；保持现有策略结果可复现，并持续检查输入没有未来信息。
2. **构造可复现的训练、验证、测试集**：以完整运行场次、种子与地图为单位划分，避免把同一轨迹的相邻片段分散到训练和测试；记录场景、版本和适用范围。未执行动作的结果不能当作已观测标签。
3. **改进并验证 CPU 状态转移预测**：首轮混合模型已完成，预测误差落后于规则参考。应进一步考虑外生任务/故障与不确定性，并在保留原结果的前提下改进；再验证调度闭环，不预设学习方法更优。
4. **补齐业务与论文证据**：在有真实资料时核对样本类别、规则、布局和操作过程；否则保留可追溯公开来源与明确的仿真假设。记录失败、计算开销和适用边界。

训练数据量、预测步长和异常阈值目前都不应根据想要的结果倒推。现有 20 场多点实验中各策略均完成任务，不能据此宣称模型已解决异常停滞或优于强传统调度。
