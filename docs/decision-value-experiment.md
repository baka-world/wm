# 样本转运预测的决策价值：CPU 小规模验证

## 结论与范围

这轮验证发现：在固定的有限候选和短期评分下，离线未来信息对少量决策有参考价值，但**尚未证明现有学习状态模型能够稳定改善调度**。不建议据此扩大网络或立即进入 GPU 正式训练。样本太小、站点故障未形成实际站点等待、候选集和决策点均受限，因此也不能得出“世界模型没有价值”的结论。

本报告根据本地 CPU 实际运行生成：初测与确认组各 12 个场景、每场 6 个调度策略，总计 144 次闭环运行；每场各取前 2 个可比较决策点，共 48 个决策点、188 个候选分支。每种策略在 24 场中均完成 144/144 个任务。全部闭环及候选分支记录中，离散节点重合或对向交换违规为 0；这不是连续空间或真实机器人安全证明。

[初测逐项记录](../examples/evidence/decision-value-20261108/pilot-decisions.json.gz)、[确认组逐项记录](../examples/evidence/decision-value-20261108/confirm-decisions.json.gz)包含场景配置、状态、各候选预测和实际分支结果；[两组汇总](../examples/evidence/decision-value-20261108/)及[本地初测日志](../validation/logs/decision-value-pilot-local-20261108.log)、[确认日志](../validation/logs/decision-value-confirm-local-20261108.log)、[85 项本地测试日志](../validation/logs/decision-value-tests-local-20261108-v2.log)一并保存。位置使用稳定散列键，以比较位置变化，未分发上游地图坐标或路网文件；这不是对真实数据的脱敏保证。所有实验任务均为合成。

[GitHub Actions 决策价值运行 42523304631](https://github.com/lieuyimo/wm/actions/runs/42523304631) 和 [原型回归运行 42523304707](https://github.com/lieuyimo/wm/actions/runs/42523304707) 均成功，后者运行 84 项测试。两者 PR 头提交为 `ce7def2fd12d88f15cb69161ae42709dac446e5c`；GitHub 的 PR 检出使用临时合并提交 `2b6d693a374e2930c796d6169be99fe5d14e89ac`。云端初测和确认分别消耗约 17.0 和 18.3 秒进程 CPU 时间；除环境和计时字段外，云端与本地逐项结果一致。云端[完整决策日志](../validation/logs/decision-value-action-42523304631.log.gz)、[完整回归日志](../validation/logs/decision-value-regression-action-42523304707.log.gz)及以 `ci-` 开头的全部云端数据也已归档。

## 既有系统与边界

现有 `nearest`、`world`、`rule`、`rollout`、真实一步转移记录、固定的混合线性状态模型和可观察调度回调均予以复用。世界预测的规则与学习状态模型采用相同候选、后续规则和预算；原有四种调度器则以原实现运行，其计算量不相等。旧的 `world` 是可解释时间预测，不是深度神经网络。`rollout` 基于可观察状态和估计持续时间，不知道未来故障或到达。

本次仅在仿真器中增加默认关闭的机器人**移动暂停**，不改变 `Observation` 或训练数据模式。暂停时机器人保留当前位置，联合恢复不得移动它；服务是否继续不受此配置影响，因此它不等于完整机器人故障模型。原型仍未连接 Lay2Graph 或真实设备，不支持任务转交、完整在线重分配或动态外部任务 API；紧急任务是预设释放时刻到来后才对策略可见。

## 配置及指标

地图使用[公开塔尔图医院路网](source-backed-hospital-scenario.md)和 [Open-RMF 诊所演示图](multiple-locations-experiment.md)，固定上游版本并检查 SHA-256。每张地图两台机器人、六项人工任务；初测种子为 11000/12000，确认种子为 11001/12001。任务时间表与旧训练、验证、测试及另一组新种子做去重检查。该检查并不能证明合成任务代表真实医院。

每个种子设正常、已有短站点中断、集中到达、紧急任务、共享站点争用和 R1 第 10–15 步移动暂停六种条件。集中到达的释放时刻为 0、0、0、4、4、4；紧急任务在第 8 步释放，截止时间是起始机器人静态路径和服务先验下界再加 5 步。所有新增数量、日期、故障时间、任务与站点用途均为**仿真假设**，不是临床 SLA。原图路线和非测试资料的适用性见原来源说明；工作站接收容量和实际载荷尚未建模。

`restricted_mean_flow_ticks` 对已完成任务使用交付步减释放步；未完成任务以场景结束步计算截断下界，因此不能当成最终真实完成时间。等待时间同理区分已分配样本均值与未分配样本的截断值；逾期数按已有 `late_count` 定义，未设截止时间则为 null。站点不可用等待为机器人在服务站且站点不可用的步数；`blocked_station_target_attempts` 只是目标站被占时的受阻尝试代理。`path_search_calls` 统计真实执行中普通路径搜索调用，`recovery_plans` 统计有限恢复计划事件；二者均不是任务重分配次数，也不统计 rollout 内部全部搜索。

恢复指标是中断结束后到下一次取样或交付的时间；场景结束仍无进展为右截断，中断结束时已无待处理任务为不适用。该指标不把正常排队判定为异常停滞。CPU 数字为本次进程时间，不能作为其他机器的性能保证。

## 调度对照

以下是 24 场各策略的描述性平均值；每张地图和条件只有两个种子，跨地图平均不能替代分场结果。

| 策略 | 完成任务 | 平均截断流转步数 | 合成紧急任务逾期 | 每场平均 CPU 秒 |
| --- | ---: | ---: | ---: | ---: |
| nearest | 144/144 | 81.556 | 3/4 | 0.0349 |
| world | 144/144 | 80.250 | 3/4 | 0.0353 |
| rule | 144/144 | 80.653 | 3/4 | 0.0346 |
| rollout | 144/144 | 79.389 | 3/4 | 0.1634 |
| 同预算规则状态预测 | 144/144 | 84.201 | 2/4 | 0.1983 |
| 同预算学习状态预测 | 144/144 | 85.375 | 2/4 | 0.1673 |

学习状态预测在 24 场中有 7 场截断流转时间小于规则状态预测、17 场更大；结果会因地图和负载改变，不能从均值推断稳定优势。由于不同方法可能选择不同动作并因此面对不同拥堵时刻，闭环结果不等于单独验证预测误差导致的效果。每场的等待、恢复、搜索次数、CPU 和配置见压缩数据与汇总。

四个短站点中断场景中，各策略均没有发生站点不可用期间的站内服务等待，因此**不能据此评价工作站故障恢复能力**；可观察中断仍可能影响调度。移动暂停计数表示机器人有未到达的目标且未在服务时处于暂停窗口；该计数不证明它在没有暂停时一定能够移动或造成了额外延迟。其他场次计数为零，不能将没有暴露的场次算作故障恢复成功。取送点用途、机器人数量和任务不代表原医院实测运营。

## 同一状态的反事实分析

对原 `world` 轨迹中的前两个有效决策，记录可见机器人、样本和站点状态，并枚举最多 8 个不冲突的分配批次，包含等待。每个候选以同样初始场景、种子和实际已执行分配前缀独立重放；后续均用当前可见状态上的最近距离规则。真实服务时长由种子、样本、阶段与站点确定，避免不同调度顺序消耗不同随机序列。重放先检查观测及隐藏历史一致；这些隐藏状态不进入在线策略。

模型从同一当前观测出发，对每个候选进行 20 步预测，使用相同后续规则。评分为每步“已知未完成任务数 + 4 × 已知且已逾期未完成任务数”的累加，平分时比较剩余静态路径距离。数字 4 与时间范围是预先固定的实验设定，不是临床风险权重。离线参考用各分支仿真的真实后果按相同评分选择，仅在事后计算，**不是可在线部署的策略或全局最优解**。

- 两个预测器在 48 个决策点中，有 8 次选择了不同候选；在固定后续规则的完整分支中，这 8 次对应的截断平均流转时间均相同。
- 规则状态预测在 40/48 个决策点与离线参考取得相同的完整评分；学习状态预测也为 40/48。两者各有 2 个决策的**主评分**高于离线参考；其余评分差异来自距离平分规则。
- 按离线参考选出的分支与规则状态预测选出的分支相比，完整运行的截断平均流转时间在 5 个决策点较低、41 个相同、2 个较高。参考按 20 步评分选择，因此完整运行可能更差；不能把它当成长期收益上界。
- 对 188 个候选分支，机器人位置和当前已知样本状态同时正确的数量如下。不同分支来自相同场次，彼此相关，不能把分母视作 188 个独立统计样本。

| 预测范围 | 规则状态预测 | 学习状态预测 |
| --- | ---: | ---: |
| 1 步 | 180/188 | 163/188 |
| 5 步 | 155/188 | 109/188 |
| 20 步 | 48/188 | 12/188 |

188 个候选分支中，有 148 个在窗口内出现新任务、10 个出现站点可用性变化；现有预测器不预知这些外生变化。联合正确率只检查起始已知任务状态和机器人位置，不是对全部任务、站点、时限或未来故障的预测准确率。候选预算导致 8/48 个决策点未评估全部候选；48 个决策点来自 24 场，每场有 2 个决策点，也不是相互独立的临床案例。

## 下一步

现阶段可以继续 CPU 工作：先在事前固定的新条件中增加**实际接触站点中断**的覆盖，并报告无暴露场次；再扩展独立种子、决策时刻及候选预算，检查本次观察能否重复。不要根据本次结果倒推故障参数或只保留有利场景。

值得重点收集和检验的是：可观察的站点服务进展、机器人动作延迟和当前任务/资源争用状态，以及这些状态对候选方案排序的影响。无法从当前输入推知的未来到达和突发故障应单独建模或作为不确定性，不能作为普通在线输入。之后再依据决策增益、数据覆盖和硬件实测决定是否设计 GNN、Transformer 或其他模型；目前还没有足够证据选定更复杂架构或启动正式 GPU 训练。

## 复现

```bash
python -m unittest discover -s tests -p 'test_decision_value.py' -v
python -m lab_transport.decision_value --profile pilot --output /tmp/wm-decision-pilot
python tests/check_decision_value.py /tmp/wm-decision-pilot pilot
python -m lab_transport.decision_value --profile confirm --output /tmp/wm-decision-confirm
python tests/check_decision_value.py /tmp/wm-decision-confirm confirm
```

输出目录必须为空或不存在。程序从固定公开来源下载地图并验证哈希，使用仓库已训练参数，不训练新模型、不使用 GPU。工作流在初测结构检查通过且 CPU 预算可接受后才运行确认组。查看压缩记录可用 `gzip -dc <file> | python -m json.tool`；CPU 秒数和环境信息在不同机器上不必逐位一致。
