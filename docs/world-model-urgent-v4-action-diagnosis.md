## 二、原始 P4 vs P5 的实测结论

严格按当前可观察状态、同一候选身份配对的 297 个多候选决策中，260 个分数变化、14 个排序变化、**10 个实际动作翻转**。

| 902147 | 127 | 交换常规任务执行顺序，常规受限流转 -2.00 tick/job |
| 902220 | 62 | 常规受限流转 +3.33 tick/job |
| 903147 | 38 | 常规受限流转 +6.00 tick/job |
| 903439 | 89 | 常规受限流转 +4.00 tick/job |
| 903512 | 92 | 两个常规任务完成身份互换，常规受限均值相同 |

这些数值是两个**完整策略事实轨迹**的按 seed 差值，而非针对某一次派单动作的单步反事实因果效应。它们都没有改善急诊按时率。

特别是 `904096:76`：P4 候选前三层（急诊覆盖、急诊逾期、急诊剩余时间、常规逾期）均打平，最终常规工作量亦打平，按候选索引选择 U904096-4 stage2。P5 的预测令 U904096-3 stage1 的常规工作量约少 1.13 tick，从而改变派单；事后另一个常规任务未完成。**没有证据表明 V4 确实知道后者的未来服务时间**，必须进一步区分真实条件预测与粒子抽样误差。

## 三、具体可检验的问题：共同随机数没有按“服务会话”对齐

原始 `UrgentWorldPolicy._score` 对不同合法匹配复用 `1810+tick*1009+particle` 随机生成器种子，这是正确的意图，但 `SessionRuleDynamics.predict_next` 对每个当前 eligible 的服务会话按列表顺序消耗 `rng.random()`。

不同候选可能导致不同数量或顺序的有效服务查询；此时同一物理服务会话可能得到不同的随机数，造成 **Monte Carlo coupling** 不完全一致。此处是可测量的采样混杂风险，不直接证明原 V4 决策错误。

为隔离这个因素，新增实验层的 `--random-coupling keyed`：

- 对每个合法服务查询使用 `(场景 seed, 粒子, 当前预测 tick, robot_id, sample_id, phase, station_id)` 生成稳定均匀数。
- **同一查询不受其他候选的查询顺序或数量影响**。
- 真实仿真 seed、服务真值、设备故障和复检键不作为预测输入。
- 不修改 V4 网络或 checkpoint，不修改业务任务时限和评分、不增加粒子、不选择场景或调整权重。
- P4 Rule 完全不依赖服务随机数，因此新旧 P4 在同样场景、调度规则下应逐组一致；若不一致则视作实验实现错误。
- 新实验仍为已见开发种子的 post-hoc diagnostic ablation；即使有改善，也不能宣称独立泛化或因果模型优势。
