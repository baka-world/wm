# 状态转移模型第二轮：固定的改进与验证方案

首轮结果见[状态转移实验](state-transition-experiment.md)：学习模型在服务完成识别和多步联合预测上明显落后于显式规则参考。首轮代码、指标和输出已留存；本轮是看到首轮结果之后进行的改进，不能把它描述为首轮预设方案。

## 本轮运行前固定设置

- 沿用塔尔图训练种子 3000–3011、验证种子 4000–4003、两种条件及 `nearest`/`world` 两种采集策略；一整场的所有转移始终属于同一组。
- 为避免重复使用首轮测试场景，使用**新种子**：塔尔图 9000–9003、诊所 10000–10003，均按两种条件及两种采集策略运行，每张地图各 16 场。模型参数不会使用诊所轨迹训练；但研究者已看到同一诊所地图的首轮测试，不将其描述为研究者完全盲测的新地图。
- 在原移动特征上增加“已处于目标点时保持不动”的特征，以区分确实需要停留与需要前往目标。训练和预测仍只使用当前观测、静态地图和当前分配，不使用未来事件或真实服务剩余时间。
- 两个分类器仍为 CPU 线性模型，全批量梯度下降 180 轮；移动和服务学习率均为 1.0，L2 为 0.001。分别保存第 35、90、180 轮的候选参数，服务类别权重仅由训练集计算。
- **仅用验证集**选取一个训练轮数：`选择分数 = 0.5 × 已知实体单步联合准确率 + 0.5 × 服务完成事件 F1`。F1 按精确识别的服务完成事件计算；分数相同选择更少轮数。固定参数后才计算新测试种子；不根据测试集调整模型。
- 保持首轮相同的规则与保持不变参考、动作信息、指标、离散预测检查和 3/5 步事后条件窗口筛选；不对比不同的任务或扰动序列，不把事后筛选条件给模型作为在线知识。
- 首轮运行后发现不同种子可能产生相同任务时间表；因此第二轮分别检查“只看任务取送和释放时刻”和“任务加站点中断”两种跨集合重复，发现重复即拒绝运行。正常和中断条件有意配对、属于同一集合。该检查不改变既定种子、参数选择或模型训练。

此模型仍是混合状态转移模型：地图与任务生命周期规则为显式代码；模型学习已知任务的移动及服务完成，不生成未来任务、不预测站点故障，也没有接入真实机器人或调度闭环。

多机器人移动按当前步顺序建模：训练后一个机器人的候选时使用前一个机器人实际移动来构造候选屏蔽；推理时使用模型自己对前一个机器人的预测。这个训练方式的条件差异需要记入误差来源，推理不读取其他机器人真实下一位置。

## 第二轮结果（2026-11-07）

按预设，验证集在第 35、90、180 轮的选择分数分别为 0.6560、0.7215、0.7368，选择第 **180 轮**。同一验证集参与了模型选择，其成绩不能作为独立测试结论。训练使用 48 场、11,848 条非终止转移；训练集没有超时场次，均为合成任务。

事后加入的场景去重检查覆盖 24 组不同任务时间表、配对产生的 48 组正常或中断场景，**跨训练、验证和测试没有重复任务时间表**。这不等于这些仿真场景能代表真实医院分布；诊所地图也不是研究者未曾看到的盲测地图。

| 新测试种子 | 下一机器人位置准确率：规则 / 学习 | 服务完成事件识别率：规则 / 学习 | 已知实体联合准确率：规则 / 学习 |
| --- | ---: | ---: | ---: |
| 塔尔图（16 场；176 次服务完成） | 100.0% / 87.0% | 68.2% / 70.5% | 97.1% / 72.4% |
| 诊所演示图（16 场；176 次服务完成） | 99.6% / 91.6% | 76.1% / 75.0% | 92.9% / 80.0% |

服务完成事件的精确率分别为：塔尔图规则 68.2%、学习 81.6%；诊所规则 70.5%、学习 79.5%。学习模型在这一项事件识别上有改善空间，但**总体联合预测仍低于规则参考**，不能声称调度策略因此更好。联合准确率只统计机器人位置和当前已知任务状态；未知新任务和故障没有被预测。

| 新测试种子 | 3 步条件窗口：规则 / 学习联合准确率 | 5 步条件窗口：规则 / 学习联合准确率 |
| --- | ---: | ---: |
| 塔尔图 | 93.4% / 62.4%（3,480 / 3,872 窗口） | 89.8% / 55.2%（3,190 / 3,840 窗口） |
| 诊所演示图 | 81.7% / 60.9%（1,137 / 1,497 窗口） | 71.5% / 47.7%（897 / 1,465 窗口） |

多步窗口仍按首轮规则**事后筛选**，这些条件并不是模型在线可提前知道的信息。第二轮使用新的测试种子，因此不能把两轮测试表的百分比差直接解释为严格配对的改进；选择依据只能是预先指定的验证集。模型还未参与任务分配，以上数据不是闭环调度收益。

固定参数与[逐场结果](../examples/evidence/dynamics-revision/dynamics-results.json)以及[本地运行日志](../validation/logs/state-transition-revision-cpu-2026-11-07.log)均已保存；[首轮结果](state-transition-experiment.md)同时保留。该诊所地图没有用于训练参数，但曾在首轮评估中被研究者看到，不是研究者完全盲测地图。

### 复现

```bash
python -m lab_transport.dynamics_revision \
  --hospital-map /path/to/hospital.building.yaml --tiago-config /path/to/tiago.launch.xml \
  --clinic-map /path/to/clinic.building.yaml --clinic-config /path/to/deliveryRobot_config.yaml \
  --output /tmp/dynamics-revision
python tests/check_dynamics_revision.py /tmp/dynamics-revision examples/evidence/dynamics-revision
```

输入地图均按固定来源校验；检查器验证训练与测试种子、验证集选择过程和逐场统计，CPU 时间除外。

### 查看一步预测回放

```bash
python -m lab_transport.dynamics_demo \
  --clinic-map /path/to/clinic.building.yaml --clinic-config /path/to/deliveryRobot_config.yaml \
  --model examples/evidence/dynamics-revision/dynamics-parameters.json --output /tmp/dynamics-demo
```

打开 `/tmp/dynamics-demo/report.html`，可同时查看当前状态、规则预测、学习模型预测和下一步实际状态，拖动进度条查看任务状态与机器人位置。页面使用当步**实际执行的分配**做离线对照；模型不预测新任务，页面会单独提示新增任务。输出中的地图和任务仍是公开演示地图与人工仿真任务，不是医院现场记录。
