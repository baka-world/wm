# CPU 状态转移模型：实验设定

## 目的与边界

本实验在已有仿真中训练一个轻量的、动作条件的一步状态转移模型，并检查重复使用模型进行短期预测时的误差。它服务于本科毕设的系统实现与测试，不预设模型胜过传统规则。训练标签仅来自模拟器**实际执行的分配**，不把未执行候选的结果当作已观测事实。

环境复用[多取送点实验](multiple-locations-experiment.md)的固定公开地图和时间估计：塔尔图医院多取点与 Open-RMF 诊所演示图；样本点用途、任务序列、中断与部分操作时长均保留原文明确标注的仿真假设，没有新造临床期限。每场 2 台机器人、6 个任务、10 秒仿真步、至多 350 步，正常与短中断两种条件。

## 运行前固定的划分

按**完整场景种子**分组，配对条件和采集策略一起划入同一集合；不得将同一场景的邻近状态分别放入训练与测试。各集合的种子不与之前的学习预测器训练或测试种子重叠。

| 集合 | 地图 | 场景种子 | 条件与采集策略 | 场数 |
| --- | --- | --- | --- | ---: |
| 训练 | 塔尔图 | 3000–3011 | 正常/短中断 × `nearest`/`world` | 48 |
| 验证 | 塔尔图 | 4000–4003 | 同上 | 16 |
| 已见地图测试 | 塔尔图 | 5000–5003 | 同上 | 16 |
| 未见地图测试 | 诊所演示图 | 6000–6003 | 同上 | 16 |

验证集用于报告，不根据测试集调参数。固定采用 35 轮全批量梯度下降：移动候选线性 softmax 学习率 0.2，服务进度二分类学习率 0.15，L2 系数 0.001；服务完成与未完成类别权重按**训练集**频数平衡。权重初始为零，不需要随机初始化或 GPU。单个最终边界为 `end_of_run` 的转移统一不参与训练和一步评估。

## 输入、输出与模型

输入是 [Observation](../lab_transport/transition_schema.py) 中当下已知的机器人、已释放任务、站点和静态地图，以及这一时刻实际执行的分配动作。样本及机器人 ID 只用于匹配状态、动作，不作为数值训练特征；种子、未来任务/故障和真实剩余服务时间不能成为特征。

模型由已知规则和两个学习部分组成：

- 利用地图和当前位置列出可等待或移动的相邻节点，以路线距离变化、相对拥挤及当前任务阶段等特征，学习对候选移动的评分。
- 在机器人已经到达且站点当前可用时，根据已用时间、已观测服务时间估计及当前任务阶段，学习预测本步服务是否完成。
- 样本生命周期、当前站点不可用时暂停服务、单步邻接与离散冲突检查使用明确规则。模型保留当前站点可用状态和服务均值，不预测未知的未来中断，也不凭空生成未来新任务。输出是部分可观察状态的点估计，不是概率校准或真实医院安全保证。

这种组合属于轻量**混合状态转移模型**：地图约束和任务状态机由代码提供，移动选择与服务完成由仿真数据训练。它不是视频生成或完整环境生成模型。模型的离散移动约束是预测后处理，真实运行仍由仿真器执行自己的安全检查。

## 对照与评估

对照包括保持当前状态的简单参考，以及根据当前已知地图、占用、服务均值计算下一步的显式规则参考。后者不读取将来的占用、真实服务剩余量或恢复计划，也不是 CBS/LaCAM 完备规划器。

一步评估在相同测试转移和已执行动作上比较：机器人下一位置准确率、实际移动时的位置准确率、已知任务状态准确率、实际状态变化的识别情况，以及机器人位置与已知任务状态同时正确的比例。应同时报告样本量、类别分布和按场次汇总，避免大量不动/状态不变掩盖错误；新到任务不作为已有任务的预测输出，并单独计数站点可用状态变化和新任务到达。

多步预测预设跨度为 3 和 5 步。初始动作取该时刻已执行动作，后续假设没有新分配；为了可与真实执行比较，只在**事后筛选**的窗口计算：窗口内没有后续新分配、没有新释放任务、没有站点可用性变化，且没有结束边界。报告符合条件的窗口数与排除数。这只是已观测轨迹上的条件诊断，未来是否发生任务或中断在在线决策时不可知，不能将筛选结果当作真实运行中的提前知识或反事实调度收益。

所有对照共享同样的历史状态、静态地图和分配动作；不将未来真实状态传给模型。模型只预测当前已知任务，不能被用来声称预知随机到达或隐含故障。固定种子及拆分、完整场次数、每步和每场结果均须记录；若学习预测较差或多步误差累积，也照实保存。

## 首轮结果（2026-11-07）

CPU 运行的 48 个训练场景获得 11,848 条非终止转移，提取 22,120 条移动候选训练样本和 1,532 条服务样本（其中完成 528 条）；没有因实际位置不在允许候选中而排除的移动样本。训练、验证及两组测试的场景均完成 6 个任务。验证和测试每组 16 场；同种子下的两种条件与两种采集策略是配对场景，不应当作独立医院或患者。

| 测试地图 | 下一机器人位置准确率：规则 / 学习 | 实际服务完成的识别率：规则 / 学习 | 已知实体联合准确率：规则 / 学习 |
| --- | ---: | ---: | ---: |
| 塔尔图（3,908 步；176 次服务完成） | 100.0% / 88.3% | 65.9% / 45.5% | 97.6% / 74.2% |
| 未参加模型训练的诊所图（1,474 步；176 次服务完成） | 98.2% / 90.7% | 81.8% / 45.5% | 91.9% / 75.6% |

联合准确率仅要求**当前已知任务的状态和机器人位置**同时正确，不包括未来新到任务或站点可用性变化。每组测试中分别出现 80 个新释放任务及 16 次站点可用性变化；模型没有预测这些外生事件，不能把它们排除后声称预测了完整世界。高比例的任务状态不变也不能代替服务完成事件的识别率。

| 测试地图 | 3 步条件窗口：规则 / 学习联合准确率 | 5 步条件窗口：规则 / 学习联合准确率 |
| --- | ---: | ---: |
| 塔尔图 | 93.7% / 63.3%（3,468 / 3,876 窗口） | 89.7% / 55.1%（3,168 / 3,844 窗口） |
| 诊所演示图 | 82.2% / 52.6%（1,088 / 1,442 窗口） | 75.1% / 37.3%（842 / 1,410 窗口） |

这些窗口是按上文规则**事后筛选**的，不代表模型能预先知道没有新任务或故障。首轮学习模型明显落后于使用已知地图与服务均值的规则参考，且服务完成识别偏弱；它不能用于宣称调度收益。逐场统计、固定参数和[本地完整运行输出](../validation/logs/state-transition-cpu-2026-11-07.log)保留在仓库。移动分类器训练时以前一个机器人**实际**移动作为同一步顺序建模的条件；评估和多步推演时使用模型自己的前序预测，因此没有在预测时读取另一台机器人的真实下一位置。

**事后数据审计发现一个限制**：虽然首轮训练和测试的随机种子不同，塔尔图正常条件下训练种子 `3001` 与测试种子 `5001` 生成了完全相同的任务取送与释放时间表，因此两种采集策略对应的 2 个测试场景并非全新的任务时间表。两场服务时长抽样并不完全相同：12 个任务阶段中有 8 个抽样值相同。两场不应简单视为完全不同的工作负载；首轮总体指标保留，但其泛化解释需要打折。后续实验增加了按地图、任务时间表和中断区间检查跨集合重复的步骤。

[逐场结果](../examples/evidence/dynamics-pilot/dynamics-results.json)和[模型参数](../examples/evidence/dynamics-pilot/dynamics-parameters.json)仅含合成任务统计与权重。每次预测均执行离散占点、换边及地图邻接检查；这是代码中的预测约束，不是模型学会安全，也不是物理安全证明。

首轮结果用于诊断。若进一步改进特征或训练轮数，必须保留本次结果、说明调整依据，用验证集选择，并使用新的未参与调参的测试种子；由于研究者已看到这张诊所地图的首轮结果，之后不能把同一张图称为研究者完全盲测。

### 复现

```bash
python -m lab_transport.dynamics_experiment \
  --hospital-map /path/to/hospital.building.yaml --tiago-config /path/to/tiago.launch.xml \
  --clinic-map /path/to/clinic.building.yaml --clinic-config /path/to/deliveryRobot_config.yaml \
  --output /tmp/dynamics-pilot
python tests/check_dynamics_experiment.py /tmp/dynamics-pilot examples/evidence/dynamics-pilot
```

地图和配置均按既有适配器校验固定版本；原始地图不会提交到本仓库。检查器比较分组、计数与留存结果，排除会随机器变化的训练 CPU 时间。
