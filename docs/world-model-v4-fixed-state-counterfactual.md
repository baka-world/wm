# PR #18：冻结合法状态的 V4 多种子决策稳定性与配对实际后果实验

## 执行前冻结协议

本轮不再继续无休止地猜测模型为什么不稳定。必须**实际执行**固定合法状态实验，严格区分三个问题：
1. 同一个观察、同一合法候选下，V4 换预测采样种子后，派单是否稳定？
2. 固定全部前缀事实后，不同候选在同一外生服务和复检规则下，实际后续完成时效是否不同？
3. 采样稳定的候选是否真的更好，还是终端价值模型稳定但排序错误？

### 现有事实及选取范围

之前20组已观察合成场景的10次Rule/V4动作翻转，有9次Rule对两候选业务分数打平，8次对3粒子删一敏感。急诊改善主要来自905147:0和905585:0。为覆盖正向、常规任务、后段不利决策，**先锁定**：
- 905147:0（急诊正向案例）
- 905585:0（另一急诊正向案例）
- 905220:41（常规任务排序案例）
- 905804:0（急诊分配与迟到下界）
- 906195:138（后期稳定但可能错误的常规选择）

完整场景index、观测哈希、合法候选数和原始ZIP校验在
\`experiments/world_model_integration/urgent_world_model_integration/fixed_state_protocol.json\`。
此处是**结果已知后的定向诊断**，不能用于显著性、无偏训练泛化或真实企业部署收益主张。

### 模型预测重复

每个状态严格重放原 P5 之前的动作，校验每一处合法分配及观测SHA，目标候选与原Actions日志逐个匹配。冻结V4 checkpoint SHA：
\`60c8a6c3d832da3e6519072688ea099f64ae120ba19d3bd2ec705f7f1a11ac0c\`。

先使用原始场景seed预测一次，要求所有原始候选的**每粒子分数及最终选择**逐项复现封存记录。随后另用7个预先冻结的新预测采样seed；每次3粒子、H5 + 公共规则续推20 tick、所有候选、公平键控随机数配对，V4权重/业务评分不动。只更改预测采样的随机数键，不改变真实仿真外生seed。

记录每个采样seed的候选分量、粒子分数、选中动作、排序分歧、选择频率及模型调用量。与Rule使用同一个冻结可观察状态作参考。

### 实际未来的条件对照

在目标tick之前，**完全重放原P5的动作前缀**；在目标tick强制执行各个合法候选一次；之后都使用同一个固定P1急诊优先策略直到仿真终点。真实系统服务时长已按(seed,sample_id,phase,station_id)键控，条件复检按(seed,job_id)键控；因此真实候选共享同一个外生场景而不会因为调用顺序改变服务随机数。

逐候选记录任务级急诊按时、逾期下界、未完成、常规/全部流转，以及安全、事件与历史哈希。将所有候选按既定\`judge_score\`比较，作为**事后固定P1续推条件下的有限候选排序**；不得称为全局最优调度或条件期望收益。与预测重复选择比例逐状态比较。未来真值绝不能回流进V4输入或模型超参数。

没有证明模型事件预测更准之前，不能从整体业务回报反推出模型Brier误差；也不能将被挑选案例的结果当作盲测。
