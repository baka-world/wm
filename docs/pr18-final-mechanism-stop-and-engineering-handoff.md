# PR #18 最终机制诊断与研究停止裁决（2026-11-11）

## 最终裁决

**停止继续开展细粒度模型诊断、反事实分解及参数试探，但不停止世界模型研发。后续工作的第一优先级仍是完善“预测整个样本转运系统未来状态”的世界模型；调度器、仿真器和演示界面是用于集成验证它的配套系统，而非取代研究主线。**

## 后续研发优先级：世界模型第一，而非普通业务系统

论文《基于世界模型的样本转运调度系统设计与实现》继续采用仿真方案，研究对象是**上层多机器人样本转运系统的条件状态转移模型**，不是低层运动控制/VLA，也不是单纯的急诊任务打分器。此前交接将“系统闭环和演示”置于第一位属于方向偏差，现予以纠正。

### P0（第一优先级）：世界模型能力建设

**目标**：给定当前可观测系统状态 `S_t` 与候选调度动作 `A_t`，能够预测未来一个或若干调度步的系统状态 `S_{t+h}`，并为多候选调度比较提供可追溯的预测依据。

核心输出至少涵盖：
- 样本/任务：当前所属工序、阶段完成、预计剩余工作与任务逾期风险；
- 工作站/资源：服务会话、忙闲与容量占用、排队/等待、可观察异常影响；
- 机器人/调度：机器人任务归属、路径推进的可观察结果、任务分配引起的资源竞争；
- 不确定性：V4 已有的服务事件概率及预测采样不确定性。未知的未来复检、故障和新任务不得以“已知事实”泄漏进入输入。

**现状分层**：V4 当前主要学习的是“符合条件的服务会话下一步是否完成”的概率；系统状态推进、工序释放、容量限制和导航等仍大量由规则模型承担。因此，系统的整体预测应明确称为**混合式世界模型（神经服务事件模型 + 确定性业务状态转移）**，不能把 V4 单独描述成已经完整学习了整个样本转运系统动力学。

**工程实施顺序**：优先梳理并固化统一的 `observe → encode(S,A) → predict_next/predict_rollout → decode predicted state and uncertainty` 接口；复用现有 V4、WorkflowDynamics、合法状态转换及规则约束，不从零重造可验证的确定性动力学。先达到可重复的完整系统状态预测，再决定是否必须扩展学习模块。不能为了形式上的“神经网络更大”而直接训练新模型。

### P1（第二优先级）：世界模型驱动的调度决策闭环

保持现有 CP-SAT 合法候选生成及运动/资源安全模块。让世界模型对**同一个可观察系统状态下的合法候选动作**逐一预测后续任务、排队和资源状态，再用统一、事先说明的业务目标比较候选。Rule 作为可核对的基线/故障回退，不应成为论文主角。

重点验收：世界模型确实参与预测和选择；展示每个候选的预测状态、选择理由、实际下一状态与偏差。必须区分“系统已接入模型”与“已获得稳定性能收益”；后者现阶段没有证据可宣称。

### P2（第三优先级）：必要的系统封装与演示

只补齐支撑上述 P0/P1 验收必需的业务闭环、状态展示、运行监控、异常与重新调度、配置、日志和可复现启动。UI、美化、额外基础设施、底层运动控制以及与世界模型无关的功能拓展均不得挤占 P0。

### 研究与工程的停止界限

**停止的是：** 在同 5 个事后选定状态上反复换种子、粒子数、终端长度和权重，追逐微小排序差异；不再通过单案例微观诊断制造下一轮实验。

**不停止的是：** 建设并验证能够预测整个样本转运系统任务与资源状态的世界模型，这是论文最重要的技术内容。若 P0 核心能力存在明确缺口，应直接做有定义、可验收的实现工作，而不是延续无边界的个案归因审计。

**下一任务的排序固定为：P0 世界模型 → P1 模型辅助调度 → P2 工程演示与论文验收。**
